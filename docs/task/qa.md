# Q&A по треку DevOps, 2 октября 2026

Ответы эксперта трека на вопросы участников на онлайн-сессии (запись в МТС Линк, 32 минуты).
Ниже выжимка по смыслу, а не дословная расшифровка. В последней колонке указано, как ответ учтён в решении.

## Окружение проверки

| Вопрос | Ответ эксперта | В решении |
|---|---|---|
| Архитектура проверочной машины | amd64 основная, arm64 возможна | только amd64: preflight останавливает установку на другой архитектуре, указано в «Ограничениях» README |
| Ресурсы | 4 vCPU, 16 ГБ RAM, диск до 100 ГБ (можно меньше) | минимум 4 vCPU, 8 ГБ, 30 ГБ, рекомендуем 16 ГБ: лимиты памяти заданы с запасом |
| Образ ОС | Ubuntu 24.04, например cloud image | проверено на cloud image (Proxmox) и раннере GitHub `ubuntu-24.04` |
| Single node снижает баллы? | нет, ресурсы участника ограничены | [ADR-01](../adr/01-single-node-kubeadm.md): одна нода на kubeadm |
| IPv6-only приложение | можно, но может усложнить проверку | IPv4 |

## Сеть и доступ к ресурсам

| Вопрос | Ответ эксперта | В решении |
|---|---|---|
| Есть ли интернет у проверяющих (образы, чарты, пакеты) | да, считаем, что всё доступно; офлайн-установка не требуется | установка тянет пакеты, образы и чарты из интернета |
| Можно ли задать зеркало или прокси реестров | можно, лучше указать | зеркало Docker Hub `mirror.gcr.io` в containerd ([ADR-06](../adr/06-registry-and-network-resilience.md)) |
| Из РФ без VPN у участника не работали Docker Hub, get.helm.sh, registry.k8s.io, ghcr.io, mirror.gcr.io, чарты на `*.github.io`; работали quay.io, pkgs.k8s.io, GitHub, PyPI | эксперт проверит доступность сам, ответ обещан в чате; доступность зависит от провайдера; про Helm: можно скачать чарт заранее и ставить без get.helm.sh | см. ADR-06 и раздел «Ограничения» README |

## Требования к решению

| Вопрос | Ответ эксперта | В решении |
|---|---|---|
| Нужно ли автоматизировать подготовку чистой Ubuntu, зависимости и создание кластера | да, от чистой ВМ до кластера | `make deploy`: Ansible от пакетов ОС до Argo CD |
| Самоподписанный TLS или валидный сертификат | самоподписанного достаточно | cert-manager, свой CA, `make ca-cert` |
| Куда отправлять логи | лучше агрегатор в кластере (например, Loki) и Prometheus; это плюс | Fluentd → Loki, Grafana |
| Как проверяют идемпотентность | повторным развёртыванием с чистой ВМ; повторный прогон на уже установленном кластере не требуется | проверяем оба случая: CI запускает `make deploy` дважды, второй прогон обязан дать `changed=0` |
| Как проверяют работу приложения | имя из Gateway API прописывают в `hosts` и открывают с клиента (в том числе в браузере): Hello World, логи Fluentd, метрики Prometheus | имена `*.mts-hack.local`, порты 30080/30443, раздел «Проверка» README |
| Засчитываются ли публичные прогоны CI | да, как подтверждение | [Actions](https://github.com/gifi71/mts-hack-2026/actions): e2e на чистом `ubuntu-24.04` |
| Если у эксперта не запустилось с первого раза | для сильных решений эксперты могут связаться с участником, индивидуально | |
