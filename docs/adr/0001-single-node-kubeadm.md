# 0001. Одна нода на kubeadm

## Контекст

ТЗ отдаёт приоритет kubeadm. Эксперты разворачивают решение на своей инфраструктуре по README.
Критерий «воспроизводимость» (25 баллов) учитывает число ручных действий. В CI доступен один раннер.
На Q&A 2 октября эксперт трека подтвердил: single node баллы не снижает, ресурсы участника ограничены
([docs/task/qa-2026-10-02.md](../task/qa-2026-10-02.md)).

## Решение

Кластер kubeadm 1.36 из одной ноды Ubuntu 24.04. Control plane без taint, рабочая нагрузка на нём же.
Мультиноду в рамках хакатона не делаем: она не добавляет баллов и не проверяется в CI.
Inventory разделён на группы `control_plane` и `workers`, чтобы её можно было добавить без переделки.

## Варианты

- **1 control plane + 2 worker**: эксперту нужно три ВМ, SSH и правка inventory. Больше точек отказа
  на чужой сети (MTU, firewall, VXLAN между нодами). CI такой кластер не проверит.
- **kind / k3s / minikube**: проще, но ТЗ отдаёт приоритет kubeadm.

## Последствия

- Эксперт поднимает решение на одной ВМ одной командой. Ровно этот сценарий проходит e2e в CI.
- HA нет: при потере ноды кластер недоступен. Мультинода и HA control plane вынесены в развитие.
